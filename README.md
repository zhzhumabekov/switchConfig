# Просмотр конфигураций коммутаторов Huawei

Локальное веб-приложение для просмотра конфигураций коммутаторов Huawei (VRP). Оно подключается к коммутаторам по SSH, забирает `display current-configuration` и показывает конфигурацию в структурированном виде:

- **Передняя панель стека.** Каждый порт окрашен по назначению (рабочее место, Wi‑Fi, аплинк, принтер и т.д.). Можно подсветить, где проходит нужный VLAN.
- **Порты.** Группы портов с одинаковыми настройками и таблица с поиском и фильтрами.
- **VLAN, L3-интерфейсы и маршруты.** Для маршрутов видно, доступен ли next-hop.
- **Сервисы:** AAA, RADIUS / 802.1X, SSH, NTP, SNMP, журналы.
- **Замечания.** Автоматический поиск возможных проблем: VLAN, которые не созданы; недостижимые маршруты; консоль без пароля; незашифрованные протоколы и т.п.
- **Состояние портов сейчас.** Какие порты up, down или выключены; порты, заблокированные из-за петли; счётчики ошибок; загрузка; LLDP-соседи; MAC-адреса и их IP.
- **Поиск «где подключено устройство»** по MAC, IP или имени сразу по всем коммутаторам.
- **Все коммутаторы сразу.** Общая сводка, схемы портов всех коммутаторов, единый список замечаний и таблица «какой VLAN на каком коммутаторе».

## Требования

- Windows 10/11. Пароли шифруются средствами Windows. На других ОС приложение тоже работает, но с менее надёжным шифрованием (см. [Безопасность](#безопасность)).
- [Node.js](https://nodejs.org/) 18 или новее.
- Доступ по сети к коммутаторам по SSH (порт 22) и учётная запись на них.

## Установка

```bash
git clone https://github.com/zhzhumabekov/switchConfig.git
cd switchConfig
npm install
```

`npm install` нужен один раз: он ставит библиотеку `ssh2`. Если забыть, `start.bat` выполнит его сам.

## Запуск

Дважды щёлкните **`start.bat`** или выполните:

```bash
npm start
```

Откроется `http://127.0.0.1:8080/`. Окно сервера не закрывайте, пока пользуетесь страницей. Чтобы остановить сервер, нажмите `Ctrl+C`.

Если порт 8080 занят, выберите другой:

```bash
set PORT=9000 && node server.js
```

## Первая настройка

1. На странице нажмите **«Настройки»** (или откройте `http://127.0.0.1:8080/settings.html`).
2. Нажмите **«+ Добавить коммутатор»** и заполните поля: название, IP-адрес, порт SSH (обычно 22), логин и пароль.
3. Нажмите **«Проверить подключение»**. Если всё верно, появится `✓ Подключение успешно` и имя коммутатора.
4. Нажмите **«Сохранить и забрать конфигурацию»**.
5. Повторите для остальных коммутаторов.

Пароль вводится один раз: дальше конфигурацию можно обновлять кнопкой без ввода пароля.

## Работа

- **Выбор коммутатора** — выпадающий список вверху страницы. В режиме «Все коммутаторы» они показаны вместе.
- **Обновить с коммутатора / Обновить все** — забрать свежую конфигурацию. Одновременно выполняется не больше 4 подключений.
- **Клик по порту** открывает панель с его настройками и строками конфигурации.
- **Вкладка «Исходник»** показывает полный конфиг, разбитый на сворачиваемые блоки, с поиском. Секреты в нём скрыты (`******`).
- При каждом обновлении предыдущая версия конфига сохраняется в `data/configs/<id>.prev.txt`.

## Состояние портов и поиск устройств

При каждом обновлении, в той же SSH-сессии, что и конфиг, выполняются ещё четыре команды. Все они только читают данные:

| Команда | Что даёт |
|---|---|
| `display interface brief` | Состояние портов (up / down / shutdown / петля), загрузка, ошибки. |
| `display lldp neighbor brief` | Кто подключён к порту: соседний коммутатор, IP-телефон, точка доступа. |
| `display mac-address` | Какие MAC-адреса видны на каждом порту. |
| `display arp` | Соответствие IP → MAC. |

**Где это видно:**
- **Схема панели.** Полоска внизу порта: зелёная — up, оранжевая — петля, красная — ошибки. Бледные порты — down, заштрихованные — shutdown.
- **Вкладка «Порты»** — колонки «Сейчас» и «Подключено» и фильтр по состоянию. Поиск в таблице находит порт и по MAC или IP.
- **Клик по порту** — состояние, загрузка, ошибки, LLDP-сосед и список MAC-адресов с IP.
- **«Замечания»** — порт заблокирован петлёй, магистральный порт не работает, ошибки на портах.

**Поиск «где подключено»** — поле вверху страницы. Введите MAC (в любом формате, можно часть), IP или имя и нажмите Enter. Если MAC виден на нескольких коммутаторах, сверху показывается конечный порт, а порты, через которые MAC проходит транзитом (аплинки), свёрнуты ниже.

Поиск по IP работает через ARP-таблицу. На коммутаторе доступа она содержит мало записей, поэтому для поиска по IP добавьте в список коммутатор ядра — шлюз сети.

## Имена устройств из AD, DHCP и DNS

Если компьютер с приложением в домене, по MAC-адресам с портов находятся:
- **из DHCP** — имя компьютера и IP (аренды и резервирования);
- **из AD** — описание компьютера, ОС, подразделение (OU), отключена ли учётная запись;
- **из DNS** — имена устройств со статическим IP (по обратной записи).

Где это видно:
- в колонке «Подключено» на вкладке «Порты»;
- в панели порта (колонка «Устройство»);
- в поиске: теперь он находит и по имени компьютера или его описанию.

Список **«Неизвестные устройства»** (в обзоре коммутатора и в «Все коммутаторы») показывает MAC на пользовательских портах, которых нет ни в DHCP, ни в AD, ни в DNS, и компьютеры, отключённые в AD, но включённые в сеть.

**Настройка** — «Настройки» → «Windows-серверы: AD, DHCP, DNS»:
- DHCP-серверы по умолчанию находятся автоматически в AD, их можно указать вручную.
- По умолчанию используется ваша учётная запись Windows. Можно указать другую; её пароль хранится так же зашифрованно, как пароли коммутаторов.
- Права: чтение DHCP (группа «DHCP Users»); чтение AD есть у любого пользователя домена.
- Нужны модули PowerShell `DhcpServer` и `ActiveDirectory` (RSAT).

Данные обновляются после сбора с коммутаторов (не чаще раза в 10 минут) или кнопкой «Сохранить и загрузить данные». Всё только читается, в AD, DHCP и DNS ничего не меняется. Результат хранится в `data/directory.json`.

## Сбор по расписанию и история

Пока запущен сервер, данные собираются сами. По умолчанию:
- состояние портов — каждые 30 минут;
- конфигурация — раз в сутки;
- AD / DHCP / DNS — раз в час.

Интервалы меняются в «Настройки» → «Сбор по расписанию», там же сбор можно выключить. После неудачной попытки коммутатор не опрашивается каждую минуту: следующая попытка будет через тот же интервал. Открытая страница подхватывает новые данные сама, примерно раз в минуту; вкладка и фильтры при этом сохраняются.

Каждое подключение к коммутатору — это вход по SSH, он попадает в журнал коммутатора.

**Вкладка «История»** у каждого коммутатора:
- **События:** коммутатор не отвечает / снова отвечает; аплинк упал / поднялся; петля / петля снята; появились ошибки на порту; изменилась конфигурация; новое или неизвестное устройство; устройство переехало на другой порт. Есть фильтр по типу.
- **«Что изменилось в конфигурации»:** выбираете две версии и видите добавленные и удалённые строки с указанием, к какому интерфейсу или разделу они относятся. Все версии хранятся списком, для каждой — число изменённых строк.

**Где ещё видна история:**
- **«Все коммутаторы»** — последние события по всем коммутаторам.
- **Панель порта** — «История порта»: какие устройства были на этом порту и когда.
- **Поиск** — для устройства, которого сейчас нет в сети, показывается, где и когда его видели в последний раз.

При первом сборе с коммутатора события об устройствах не создаются: он только запоминает, что где подключено. Устройства за аплинками и на портах с множеством MAC (больше 5) не отслеживаются.

## Готовые команды для исправления

Команды только показываются — на коммутатор приложение ничего не отправляет. Скопируйте их, проверьте, выполните в SSH-сессии и сохраните конфигурацию командой `save`.

**В «Замечаниях»** у каждого пункта есть блок «Как исправить»: команды Huawei VRP и кнопка «Копировать». Где решение неоднозначно, показано несколько вариантов (например, «создать VLAN» или «убрать его с портов»). Где можно потерять доступ, есть предупреждение: пароль на консоли, смена протоколов входа, ACL для SNMP. Для проблем с «железом» (петля, упавший аплинк, ошибки) — команды диагностики.

**В панели порта** — блок «Команды для порта»: сделать порт рабочим местом, принтером или точкой доступа, выключить или включить, изменить описание.
- Шаблоны берутся из самой частой настройки порта такого типа на этом же коммутаторе. Принтер — это настройка рабочего места без голосового VLAN.
- Команды считаются как разница с текущей настройкой: что убрать и что добавить. Если порт уже настроен так, будет написано, что команды не нужны.
- Описание лучше писать латиницей: многие коммутаторы Huawei не принимают кириллицу.

Работает и без сервера (при открытии `index.html` двойным кликом).

## Телефония: Cisco CME

Если телефоны регистрируются на роутере Cisco с CME (Call Manager Express), по MAC-адресам с портов коммутаторов находятся номер, подпись и модель телефона.

**Как подключить.** «Настройки» → «Добавить коммутатор»:
- тип «Cisco CME (телефония)»;
- адрес роутера, логин и пароль;
- пароль `enable`, если после входа приглашение `Router>`, а не `Router#`.

Без `enable` номера и статусы всё равно будут, но без подписей и имён: для них нужна `show running-config`.

**Команды (только чтение):**

| Команда | Что даёт |
|---|---|
| `show ephone` | SCCP-телефоны: MAC, IP, модель, номера, зарегистрирован или нет |
| `show running-config \| section ephone\|voice register` | Подписи и имена номеров, описания телефонов, SIP-телефоны |
| `show voice register pool all` | Регистрация SIP-телефонов |

Пароли из разделов `ephone` (`username … password …`) не сохраняются.

**Что видно:**
- на портах и в панели порта: `☎ 2345 Иванова А.` с моделью и IP;
- в поиске по внутреннему номеру или имени — где подключён телефон;
- в «Все коммутаторы» → «Телефония»: все телефоны с номером, именем, моделью, статусом и портом подключения. Фильтры «не зарегистрированы» и «не найдены на коммутаторах»;
- в «Истории» — события «телефон перестал регистрироваться» и «снова зарегистрирован»;
- телефоны больше не попадают в «Неизвестные устройства».

Роутер собирается по тому же расписанию, что и коммутаторы.

### Раздел «Телефоны»

Выберите роутер в списке вверху (группа «Телефония», `☎ …`). Откроется раздел с таблицей телефонов: поиск по номеру, имени, MAC, IP или порту и фильтры «не зарегистрированы», «не найдены на коммутаторах», «только SIP».

**Карточка телефона** (нажмите на строку):
- статус, модель, MAC, IP, где подключён;
- номера на кнопках (номер, имя, подпись, ephone-dn);
- конфигурация `ephone` и её `ephone-dn`.

**Изменить:** номер, имя (name), подпись кнопки (label), описание, модель, MAC при замене аппарата. Команды формируются только для изменённых полей, с `restart`, чтобы телефон получил новые настройки. Занятый номер и неверный MAC подсвечиваются, для кириллицы есть предупреждение.

Также есть готовые команды «Перезагрузить телефон» и «Удалить телефон» (только телефон или вместе с его номерами).

**«+ Новый телефон»:** MAC, модель, новый или свободный номер, имя, подпись и описание. Свободные номера `ephone` и `ephone-dn` подбираются сами.

**«Свободные номера»** — `ephone-dn`, которые не назначены ни на один телефон.

**«Телефоны на портах, которых нет в CME»** — MAC в голосовом VLAN на пользовательских портах, которых нет в CME. Кнопка «Добавить» открывает форму нового телефона с этим MAC.

Команды только показываются, на роутер ничего не отправляется. Выполните их сами и сохраните: `write memory`. Для SIP-телефонов команды изменения упрощённые: после них делается `create profile`, телефон может потребовать перезагрузки.

## Оборудование и схема сети

Вместе с состоянием портов при каждом сборе выполняются ещё 9 команд. Все только читают данные:

| Команда | Что даёт |
|---|---|
| `display version` | Модель, версия ПО, время работы без перезагрузки |
| `display device`, `display stack` | Слоты стека, их роли и состояние; кольцо или цепочка |
| `display cpu-usage`, `display memory-usage` | Загрузка CPU и памяти |
| `display temperature all` | Температура по слотам и пороги |
| `display power`, `display fan` | Блоки питания и вентиляторы |
| `display transceiver verbose` | SFP-модули: тип, длина волны, производитель, сигнал Rx/Tx и пороги, температура |

**Вкладка «Оборудование»** у коммутатора показывает:
- проблемы с командами диагностики;
- устройство и стек;
- нагрузку, температуру, питание и вентиляторы;
- таблицу SFP-модулей с оценкой сигнала.

**Что считается проблемой:**
- CPU от 80% (от 95% — важно), память от 85%;
- температура в пределах 5 °C до порога или не NORMAL;
- установленный, но не работающий блок питания; неисправный вентилятор или слот;
- стек из 3 и более коммутаторов, собранный цепочкой;
- сигнал SFP ниже порога или в пределах 2 дБ от него — только для работающих портов.

Проблемы попадают в «Замечания». В «Истории» появляются события: проблема возникла или устранена.

**«Все коммутаторы»:**
- **«Схема сети»** — связи между коммутаторами по LLDP. Коммутаторы из списка открываются щелчком. Соседи, которых нет в списке (например, ядро), показаны пунктиром. Зелёная линия — линк работает, красная пунктирная — нет. Телефоны и точки доступа на схему не выносятся.
- **«Оборудование и прошивки»** — модели, версии ПО, время работы, CPU, память, температура и проблемы по всем коммутаторам.

Если какая-то команда не поддерживается моделью, на вкладке это указано. Остальные данные показываются как обычно.

## Эталон и проверка соответствия

Эталон — это то, как должны быть настроены все коммутаторы. Он один на все коммутаторы и хранится в `data/standard.json`. Работает при запуске через сервер.

**Как создать.** Откройте коммутатор, который считаете образцовым → вкладка «Эталон» → «Создать эталон на основе …». Откроется редактор, уже заполненный так:
- шаблоны портов (рабочее место, принтер, точка доступа) — по самой частой настройке на этом коммутаторе;
- NTP, syslog, часовой пояс, SNMP-трапы — как сейчас;
- правила безопасности — по рекомендациям: только SNMP v2c/v3, SSH включён, Telnet запрещён, вход по VTY через AAA, таймаут не больше 15 минут, пароль на консоли, LLDP.

Поправьте, что нужно, и сохраните. Пустое поле или снятая галочка означают, что правило не проверяется. Можно добавить свои обязательные и запрещённые строки конфигурации.

**Что показывается:**
- **вкладка «Эталон»** у каждого коммутатора: процент соответствия, список общих правил (✓ / ✗, с командами исправления) и порты, настроенные не по шаблону своей роли. Порты сгруппированы по одинаковым отличиям, у каждой группы — готовые команды;
- **«Все исправления одним блоком»** — все команды для коммутатора сразу;
- **«Все коммутаторы» → «Соответствие эталону»** — таблица по всем коммутаторам с процентом и главными отклонениями.

С эталоном сравниваются только порты с ролью «рабочее место», «принтер» и «точка доступа». Выключенные порты, аплинки и тестовые не проверяются. Скорость, дуплекс и автосогласование тоже не сравниваются: это свойства конкретного устройства.

## Когда обновляются данные

Данные на странице соответствуют времени последнего обновления, оно указано рядом. Сырой вывод команд сохраняется в `data/state/<id>.raw.txt`: по нему можно проверить, если что-то распозналось неправильно.

## Скрипты командной строки

Для работы с одним файлом без сервера:

| Команда | Что делает |
|---|---|
| `node fetch-config.js --host 192.168.1.1 --user admin` | Забирает конфиг по SSH в `3floor.txt` и пересобирает `config.js`. Пароль спрашивается при запуске. |
| `node update-config.js` | Пересобирает `config.js` из `3floor.txt`. |
| `node update-config.js --watch` | Следит за `3floor.txt` и пересобирает `config.js` при каждом сохранении. |
| `fetch.bat`, `update.bat` | То же двойным кликом. |

Параметры `fetch-config.js`: `--host`, `--user`, `--port` (по умолчанию 22), `--out` (по умолчанию `3floor.txt`), `--timeout` (секунды). Адрес, логин и пароль можно передать через переменные окружения `SWITCH_HOST`, `SWITCH_USER` и `SWITCH_PASSWORD`.

Файл `index.html` можно открыть и без сервера, двойным кликом. Тогда показывается конфиг из `config.js`, а кнопкой «Открыть конфиг…» можно загрузить любой `.txt` с конфигурацией.

## Где хранятся данные

| Путь | Содержимое |
|---|---|
| `data/switches.json` | Список коммутаторов. Пароли в нём зашифрованы. |
| `data/configs/<id>.txt` | Последняя полученная конфигурация. |
| `data/configs/<id>.prev.txt` | Предыдущая версия. |
| `data/state/<id>.json`, `<id>.raw.txt` | Состояние портов, LLDP, MAC, ARP и сырой вывод команд. |
| `data/directory.json` | Данные из DHCP, AD и DNS. |
| `data/directory-settings.json` | Настройки AD / DHCP / DNS (пароль зашифрован). |
| `data/schedule.json` | Настройки сбора по расписанию. |
| `data/standard.json` | Эталон настроек. |
| `data/history/<id>/` | Версии конфигурации (до 300 на коммутатор). |
| `data/history/events.jsonl` | Журнал событий (последние ~20 000). |
| `data/history/devices.json` | Где и когда было видно каждое устройство. |
| `3floor.txt`, `config.js` | Файлы для работы без сервера. |

Всё перечисленное внесено в `.gitignore` и в репозиторий не попадает.

Если при первом запуске рядом лежит `3floor.txt`, он автоматически импортируется как первый коммутатор. Логин и пароль для него нужно указать в настройках.

## Безопасность

- **Пароли** шифруются через Windows DPAPI: расшифровать их может только ваша учётная запись Windows на этом компьютере. Если скопировать `data/switches.json` на другой компьютер или в другую учётную запись, пароли придётся ввести заново. На других ОС используется AES-256 с ключом в `data/.key`: кто получит этот файл, сможет расшифровать пароли.
- **В браузер пароли не передаются.** Конфиги отдаются странице со скрытыми паролями, ключами и SNMP community.
- **Сервер слушает только `127.0.0.1`**, с других компьютеров он недоступен. Запросы со сторонних сайтов отклоняются.
- **Через браузер отдаются только файлы интерфейса.** `data/`, конфиги и код сервера получить нельзя.
- **Не коммитьте** `3floor.txt`, `data/` и `config.js`: в них внутренние адреса и схема сети.

## Если что-то не работает

| Сообщение | Что делать |
|---|---|
| `Порт 8080 занят` | Сервер уже запущен (откройте `http://127.0.0.1:8080/`) или задайте другой порт через `PORT`. |
| `Неверный логин или пароль` | Проверьте учётные данные в настройках. У пользователя на коммутаторе должен быть доступ по SSH (`service-type ssh`). |
| `Коммутатор не отвечает` | Нет сети до адреса или SSH закрыт. Проверьте `ping` и `stelnet server enable` на коммутаторе. |
| `Подключение отклонено` | На этом порту SSH не слушает: проверьте номер порта. |
| `В выводе не найден конец конфигурации` | У пользователя недостаточно прав на `display current-configuration`. Нужен уровень 3 или выше. |
| Страница настроек пишет «Сервер не запущен» | Страница открыта как файл. Запустите `start.bat` и откройте её по адресу `http://127.0.0.1:8080/settings.html`. |

Для старых прошивок VRP (V200R0xx) включены устаревшие SSH-алгоритмы (`diffie-hellman-group14-sha1`, `ssh-rsa`). Ключ хоста `ecdsa-sha2-nistp521` исключён: на этих прошивках из-за него соединение падает с ошибкой `signature verification failed`.

## Структура проекта

| Файл | Назначение |
|---|---|
| `index.html`, `app.js`, `style.css` | Страница просмотра и разбор конфигурации. |
| `settings.html`, `settings.js` | Страница настроек коммутаторов. |
| `server.js` | Локальный сервер и API. |
| `store.js` | Хранение списка коммутаторов, конфигов и шифрование паролей. |
| `fetch-config.js` | Подключение по SSH и выполнение команд. |
| `live-state.js` | Разбор вывода команд о состоянии портов, LLDP, MAC и ARP. |
| `cme.js` | Разбор данных Cisco CME: телефоны, номера, подписи, регистрация. |
| `cme-cmd.js` | Команды CME: изменение, перезагрузка, удаление и добавление телефона. |
| `hardware.js` | Разбор данных об оборудовании (версия, стек, CPU, память, температура, питание, вентиляторы, SFP) и поиск проблем. |
| `directory.js`, `directory.ps1` | Чтение DHCP и AD через PowerShell, обратный DNS. |
| `collector.js` | Сбор с коммутатора (конфиг и/или состояние), запись истории. |
| `scheduler.js` | Сбор по расписанию. |
| `history.js` | Версии конфигурации, журнал событий, история устройств. |
| `diff.js` | Построчное сравнение версий (используется сервером и страницей). |
| `fixes.js` | Команды для исправления замечаний и шаблоны настройки портов. |
| `standard.js` | Создание эталона и проверка коммутатора на соответствие. |
| `ROADMAP.md` | План развития. |
| `update-config.js` | Сборка `config.js` со скрытыми секретами. |
| `start.bat`, `fetch.bat`, `update.bat` | Запуск двойным кликом. |
