# Просмотр конфигураций коммутаторов Huawei

Локальное веб-приложение для просмотра конфигураций коммутаторов Huawei (VRP). Оно подключается к коммутаторам по SSH, забирает `display current-configuration` и показывает конфигурацию в структурированном виде:

- **Передняя панель стека.** Каждый порт окрашен по назначению (рабочее место, Wi‑Fi, аплинк, принтер и т.д.). Можно подсветить, где проходит нужный VLAN.
- **Порты.** Группы портов с одинаковыми настройками и таблица с поиском и фильтрами.
- **VLAN, L3-интерфейсы и маршруты.** Для маршрутов видно, доступен ли next-hop.
- **Сервисы:** AAA, RADIUS / 802.1X, SSH, NTP, SNMP, журналы.
- **Замечания.** Автоматический поиск возможных проблем: VLAN, которые не созданы; недостижимые маршруты; консоль без пароля; незашифрованные протоколы и т.п.
- **Состояние портов сейчас.** Какие порты up, down или выключены; порты, заблокированные из-за петли; счётчики ошибок; загрузка; LLDP-соседи; MAC-адреса и их IP.
- **Поиск «где подключено устройство»** по MAC, IP или имени сразу по всем коммутаторам.
- **Все коммутаторы сразу.** Общая сводка, схемы портов всех коммутаторов, единый список замечаний и таблица «какой VLAN на каком коммутаторе».

## Требования

- Windows 10/11. Пароли шифруются средствами Windows. На других ОС приложение тоже работает, но с менее надёжным шифрованием (см. [Безопасность](#безопасность)).
- [Node.js](https://nodejs.org/) 18 или новее.
- Доступ по сети к коммутаторам по SSH (порт 22) и учётная запись на них.

## Установка

```bash
git clone https://github.com/zhzhumabekov/switchConfig.git
cd switchConfig
npm install
```

`npm install` нужен один раз: он ставит библиотеку `ssh2`. Если забыть, `start.bat` выполнит его сам.

## Запуск

Дважды щёлкните **`start.bat`** или выполните:

```bash
npm start
```

Откроется `http://127.0.0.1:8080/`. Окно сервера не закрывайте, пока пользуетесь страницей. Чтобы остановить сервер, нажмите `Ctrl+C`.

Если порт 8080 занят, выберите другой:

```bash
set PORT=9000 && node server.js
```

## Первая настройка

1. На странице нажмите **«Настройки»** (или откройте `http://127.0.0.1:8080/settings.html`).
2. Нажмите **«+ Добавить коммутатор»** и заполните поля: название, IP-адрес, порт SSH (обычно 22), логин и пароль.
3. Нажмите **«Проверить подключение»**. Если всё верно, появится `✓ Подключение успешно` и имя коммутатора.
4. Нажмите **«Сохранить и забрать конфигурацию»**.
5. Повторите для остальных коммутаторов.

Пароль вводится один раз: дальше конфигурацию можно обновлять кнопкой без ввода пароля.

## Работа

- **Выбор коммутатора** — выпадающий список вверху страницы. В режиме «Все коммутаторы» они показаны вместе.
- **Обновить с коммутатора / Обновить все** — забрать свежую конфигурацию. Одновременно выполняется не больше 4 подключений.
- **Клик по порту** открывает панель с его настройками и строками конфигурации.
- **Вкладка «Исходник»** показывает полный конфиг, разбитый на сворачиваемые блоки, с поиском. Секреты в нём скрыты (`******`).
- При каждом обновлении предыдущая версия конфига сохраняется в `data/configs/<id>.prev.txt`.

## Состояние портов и поиск устройств

При каждом обновлении, в той же SSH-сессии, что и конфиг, выполняются ещё четыре команды. Все они только читают данные:

| Команда | Что даёт |
|---|---|
| `display interface brief` | Состояние портов (up / down / shutdown / петля), загрузка, ошибки. |
| `display lldp neighbor brief` | Кто подключён к порту: соседний коммутатор, IP-телефон, точка доступа. |
| `display mac-address` | Какие MAC-адреса видны на каждом порту. |
| `display arp` | Соответствие IP → MAC. |

**Где это видно:**
- **Схема панели.** Полоска внизу порта: зелёная — up, оранжевая — петля, красная — ошибки. Бледные порты — down, заштрихованные — shutdown.
- **Вкладка «Порты»** — колонки «Сейчас» и «Подключено» и фильтр по состоянию. Поиск в таблице находит порт и по MAC или IP.
- **Клик по порту** — состояние, загрузка, ошибки, LLDP-сосед и список MAC-адресов с IP.
- **«Замечания»** — порт заблокирован петлёй, магистральный порт не работает, ошибки на портах.

**Поиск «где подключено»** — поле вверху страницы. Введите MAC (в любом формате, можно часть), IP или имя и нажмите Enter. Если MAC виден на нескольких коммутаторах, сверху показывается конечный порт, а порты, через которые MAC проходит транзитом (аплинки), свёрнуты ниже.

Поиск по IP работает через ARP-таблицу. На коммутаторе доступа она содержит мало записей, поэтому для поиска по IP добавьте в список коммутатор ядра — шлюз сети.

## Имена устройств из AD, DHCP и DNS

Если компьютер с приложением в домене, по MAC-адресам с портов находятся:
- **из DHCP** — имя компьютера и IP (аренды и резервирования);
- **из AD** — описание компьютера, ОС, подразделение (OU), отключена ли учётная запись;
- **из DNS** — имена устройств со статическим IP (по обратной записи).

Где это видно:
- в колонке «Подключено» на вкладке «Порты»;
- в панели порта (колонка «Устройство»);
- в поиске: теперь он находит и по имени компьютера или его описанию.

Список **«Неизвестные устройства»** (в обзоре коммутатора и в «Все коммутаторы») показывает MAC на пользовательских портах, которых нет ни в DHCP, ни в AD, ни в DNS, и компьютеры, отключённые в AD, но включённые в сеть.

**Настройка** — «Настройки» → «Windows-серверы: AD, DHCP, DNS»:
- DHCP-серверы по умолчанию находятся автоматически в AD, их можно указать вручную.
- По умолчанию используется ваша учётная запись Windows. Можно указать другую; её пароль хранится так же зашифрованно, как пароли коммутаторов.
- Права: чтение DHCP (группа «DHCP Users»); чтение AD есть у любого пользователя домена.
- Нужны модули PowerShell `DhcpServer` и `ActiveDirectory` (RSAT).

Данные обновляются после сбора с коммутаторов (не чаще раза в 10 минут) или кнопкой «Сохранить и загрузить данные». Всё только читается, в AD, DHCP и DNS ничего не меняется. Результат хранится в `data/directory.json`.

## Когда обновляются данные

Данные на странице соответствуют времени последнего обновления, оно указано рядом. Сырой вывод команд сохраняется в `data/state/<id>.raw.txt`: по нему можно проверить, если что-то распозналось неправильно.

## Скрипты командной строки

Для работы с одним файлом без сервера:

| Команда | Что делает |
|---|---|
| `node fetch-config.js --host 192.168.1.1 --user admin` | Забирает конфиг по SSH в `3floor.txt` и пересобирает `config.js`. Пароль спрашивается при запуске. |
| `node update-config.js` | Пересобирает `config.js` из `3floor.txt`. |
| `node update-config.js --watch` | Следит за `3floor.txt` и пересобирает `config.js` при каждом сохранении. |
| `fetch.bat`, `update.bat` | То же двойным кликом. |

Параметры `fetch-config.js`: `--host`, `--user`, `--port` (по умолчанию 22), `--out` (по умолчанию `3floor.txt`), `--timeout` (секунды). Адрес, логин и пароль можно передать через переменные окружения `SWITCH_HOST`, `SWITCH_USER` и `SWITCH_PASSWORD`.

Файл `index.html` можно открыть и без сервера, двойным кликом. Тогда показывается конфиг из `config.js`, а кнопкой «Открыть конфиг…» можно загрузить любой `.txt` с конфигурацией.

## Где хранятся данные

| Путь | Содержимое |
|---|---|
| `data/switches.json` | Список коммутаторов. Пароли в нём зашифрованы. |
| `data/configs/<id>.txt` | Последняя полученная конфигурация. |
| `data/configs/<id>.prev.txt` | Предыдущая версия. |
| `data/state/<id>.json`, `<id>.raw.txt` | Состояние портов, LLDP, MAC, ARP и сырой вывод команд. |
| `data/directory.json` | Данные из DHCP, AD и DNS. |
| `data/directory-settings.json` | Настройки AD / DHCP / DNS (пароль зашифрован). |
| `3floor.txt`, `config.js` | Файлы для работы без сервера. |

Всё перечисленное внесено в `.gitignore` и в репозиторий не попадает.

Если при первом запуске рядом лежит `3floor.txt`, он автоматически импортируется как первый коммутатор. Логин и пароль для него нужно указать в настройках.

## Безопасность

- **Пароли** шифруются через Windows DPAPI: расшифровать их может только ваша учётная запись Windows на этом компьютере. Если скопировать `data/switches.json` на другой компьютер или в другую учётную запись, пароли придётся ввести заново. На других ОС используется AES-256 с ключом в `data/.key`: кто получит этот файл, сможет расшифровать пароли.
- **В браузер пароли не передаются.** Конфиги отдаются странице со скрытыми паролями, ключами и SNMP community.
- **Сервер слушает только `127.0.0.1`**, с других компьютеров он недоступен. Запросы со сторонних сайтов отклоняются.
- **Через браузер отдаются только файлы интерфейса.** `data/`, конфиги и код сервера получить нельзя.
- **Не коммитьте** `3floor.txt`, `data/` и `config.js`: в них внутренние адреса и схема сети.

## Если что-то не работает

| Сообщение | Что делать |
|---|---|
| `Порт 8080 занят` | Сервер уже запущен (откройте `http://127.0.0.1:8080/`) или задайте другой порт через `PORT`. |
| `Неверный логин или пароль` | Проверьте учётные данные в настройках. У пользователя на коммутаторе должен быть доступ по SSH (`service-type ssh`). |
| `Коммутатор не отвечает` | Нет сети до адреса или SSH закрыт. Проверьте `ping` и `stelnet server enable` на коммутаторе. |
| `Подключение отклонено` | На этом порту SSH не слушает: проверьте номер порта. |
| `В выводе не найден конец конфигурации` | У пользователя недостаточно прав на `display current-configuration`. Нужен уровень 3 или выше. |
| Страница настроек пишет «Сервер не запущен» | Страница открыта как файл. Запустите `start.bat` и откройте её по адресу `http://127.0.0.1:8080/settings.html`. |

Для старых прошивок VRP (V200R0xx) включены устаревшие SSH-алгоритмы (`diffie-hellman-group14-sha1`, `ssh-rsa`). Ключ хоста `ecdsa-sha2-nistp521` исключён: на этих прошивках из-за него соединение падает с ошибкой `signature verification failed`.
